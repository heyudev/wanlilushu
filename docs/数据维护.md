# 数据维护

页面上的门票、开放时间、预约方式、宠物政策、油价、边境政策会随时间变化。这些信息都在 `data/research/` 里，每条带来源链接、可信度和核查日期；更新数据不需要改代码。

## 1. 数据文件

| 文件 | 内容 | 更新方式 |
|---|---|---|
| `data/route.json` | 分段、过夜点、住几晚、最佳月份、美食、提示、带狗说明 | 人工编辑 |
| `data/research/seg_*.json` | 景点门票、必乘交通、预约、宠物政策、营地、道路通行规定 | 人工或 Claude Code 核查后编辑 |
| `data/research/policy.json` | 油价、充电价、过路费、节假日免费、边境管理区通行证、带狗法规 | 同上 |
| `data/generated/*.json` | 路段里程与路线、海拔、出发城市接入、图片署名 | 脚本生成，见 README「数据管线」 |

景点条目的字段：

| 字段 | 含义 |
|---|---|
| `node` | 所属过夜点，对应 `data/route.json` 的 `id` |
| `peak` / `off` | 旺季、淡季成人票价（元），查不到填 `null`，免费填 `0` |
| `peak_windows` | 旺季价适用的日期段，如 `[["04-01","10-31"]]`，可多段、可跨年（`["12-15","01-15"]`）；淡旺季同价时不填；起止日期查不到时不填，按 4–10 月计并出现在待更新清单里 |
| `extras` | 必乘交通，`[{ "item": "观光车", "price": 90 }]`，可选项在 `item` 里写“(可选)” |
| `pets` | `禁止`、`允许(需牵引)`、`部分区域允许`、`未查到` |
| `src` | 来源链接数组，至少一个 |
| `confidence` | `high`（官方）、`medium`（OTA、新闻）、`low`（待核实） |
| `checked` | 最近一次核查日期 |
| `review_by` / `review_note` | 已知会变的日期和原因，如“限时免门票至 2026-10-31” |

`policy.json` 的条目用 `title`、`finding`、`src`、`confidence`、`checked`、`review_by` 同样的含义。

## 2. 更新流程

1. 查看待更新清单：

   ```bash
   npm run data:check                 # 默认 90 天未核查算过期
   npm run data:check -- --days 60
   ```

   清单按「到了复核日期、超过有效期未复核、政策待确认、票价未查到、来源可信度低、宠物政策未查到」分类。

2. 核查并修改 `data/research/` 里对应条目：改数值、补来源、更新 `checked`；已知会再变的写上 `review_by`。
3. 合并到应用并检查：

   ```bash
   npm run data
   npm test
   npm run build
   ```

4. 提交。页面上每条信息的可信度标签和来源链接随数据自动更新。

## 3. 自动提醒

`.github/workflows/data-check.yml` 每月 1 日运行 `npm run data:check`，把结果写进一个带 `data-refresh` 标签的 Issue（已有就更新正文）。也可以在 Actions 页面手动运行。

## 4. 用 Claude Code 核查

仓库带了项目技能 `refresh-data`（`.claude/skills/refresh-data/SKILL.md`）。在仓库目录启动 Claude Code 后，例如：

```text
/refresh-data 到了复核日期的条目
/refresh-data 黄山 宏村
```

它会按上面的字段规则联网核查、只改 `data/research/`，然后跑 `npm run data` 和测试。改动需要人工看过再提交。
