# Data maintenance

English | [简体中文](数据维护.md)

Admission prices, opening hours, reservations, pet policies, fuel prices, and border policies change over time. They are stored in `data/research/`, with source links, confidence levels, and verification dates. Updating this information does not require changing application code.

## 1. Data files

| File | Contents | Maintenance |
|---|---|---|
| `data/route.json` | Segments, overnight stops, nights, recommended months, food, travel tips, and dog notes | Manually edited |
| `data/research/seg_*.json` | Admission prices, required transport, reservations, pet policies, campsites, and road access rules | Edited after manual or Claude Code-assisted research |
| `data/research/policy.json` | Fuel, charging, tolls, holiday toll exemptions, border-area permits, and dog regulations | Same research process |
| `data/generated/*.json` | Driving distances and geometry, elevation, departure-city connections, and image attribution | Generated by the scripts listed in the [README data pipeline](../README.md#data-pipeline) |

Attraction entries use these fields:

| Field | Meaning |
|---|---|
| `node` | Overnight stop, matching an `id` in `data/route.json` |
| `peak` / `off` | Peak- and off-season adult admission prices in yuan. Use `null` if unavailable and `0` if free. |
| `peak_windows` | Date ranges for peak prices, such as `[["04-01","10-31"]]`. Multiple ranges and year-end ranges (`["12-15","01-15"]`) are supported. Omit when prices are equal or dates are unknown. Unknown dates use April–October as the fallback and appear in the audit report. |
| `extras` | Required transport, for example `[{ "item": "观光车", "price": 90 }]`. Mark optional items by including `(可选)` in `item`. |
| `pets` | Keep the Chinese data values: `禁止` (prohibited), `允许(需牵引)` (allowed on leash), `部分区域允许` (allowed in some areas), or `未查到` (not found). |
| `src` | Array of source links, with at least one source |
| `confidence` | `high` for official sources, `medium` for online travel agencies or news, `low` for unverified information |
| `checked` | Date of the most recent verification |
| `review_by` / `review_note` | Known date and reason for another review, such as the end of a temporary free-admission period |

Entries in `policy.json` use `title`, `finding`, `src`, `confidence`, `checked`, and `review_by` with the same meanings.

## 2. Update process

1. Inspect the audit report:

   ```bash
   npm run data:check                 # stale after 90 days by default
   npm run data:check -- --days 60
   ```

   It groups entries by review dates reached, stale information, unverified policies, missing prices, unknown peak-season dates, low-confidence sources, and unknown pet policies.

2. Verify and edit the corresponding entries in `data/research/`. Update values, sources, and `checked`; set `review_by` when a future change is known.
3. Generate the application data and validate the change:

   ```bash
   npm run data
   npm test
   npm run build
   ```

4. Commit the reviewed changes. Confidence labels and source links in the application update with the data.

## 3. Scheduled reminders

[`data-check.yml`](../.github/workflows/data-check.yml) runs `npm run data:check` on the first day of each month. It creates or updates one issue labeled `data-refresh`. The workflow can also be started manually from GitHub Actions.

## 4. Research with Claude Code

The repository includes the [`refresh-data` skill](../.claude/skills/refresh-data/SKILL.md). Start Claude Code in the repository and invoke it with a scope, for example:

```text
/refresh-data 到了复核日期的条目
/refresh-data 黄山 宏村
```

The first example requests entries due for review; the second requests Huangshan and Hongcun. The skill follows the field rules above, researches source pages, edits `data/research/`, then runs `npm run data` and tests. Review its changes before committing.
