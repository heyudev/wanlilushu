# 分享链接与本地存档校验

[English](share-and-storage-validation.md) | 简体中文

## 目标与影响范围

在外部方案进入页面前检查字段，避免损坏的分享链接或本地存档导致页面无法打开。涉及 `decodePlan`、`App` 的启动读取和分享结果提示；规划、费用规则和界面编辑流程不变。

分享内容是相对 `DEFAULT_INPUT` 的差异，使用 deflate-raw 压缩后写入 `?plan=`（`src/lib/share.ts:8`、`:31`）。本地保存完整方案，键为 `wanlilushu.input.v2`（`src/App.tsx:28`）。修改前，两处读取直接合并 JSON，没有字段检查（`src/lib/share.ts:39`、`src/App.tsx:34`）。`applyCustomStops` 会遍历 `custom`，`buildPlan` 会读取日期和停留晚数，因此仅保证 JSON 能解析不足以保证方案能使用（`src/lib/custom.ts:21`、`src/lib/plan.ts:136`）。

## 方案与兼容

两个读取入口共同使用 `parsePlanInput`，只接受普通对象。缺少的字段沿用默认值，未知字段不进入当前版本的方案；已知字段存在但无效时拒绝整个方案。这样既保留旧方案缺少新字段时的兼容，也避免逐字段纠正改变用户的路线或价格。

逐字段纠正可以保留部分内容，但会把损坏的路线或费用替换成默认值，页面难以说明哪些选择被改变。分别在两个入口校验会产生两套规则，因此选择统一读取校验。

校验依据是 `PlanInput`、`CustomStop` 的类型定义（`src/lib/types.ts:77`、`:274`）以及既有规划约束：成人至少一人，儿童、晚数和旅居周数为整数，驾驶时长和停留倍数必须为正，费用和里程不能为负，日期必须是有效的 `YYYY-MM-DD`。自定义地点坐标使用 WGS84 的 `[纬度, 经度]`，轨迹使用 `[经度, 纬度]`，与 `src/components/AddPlace.tsx:27`、`:74` 的写入顺序一致。枚举只接受类型定义中的值。校验不增加费用、里程和普通停留的业务上限；不新增价格默认值，也不改春节日期表。

无效本地存档返回首页并显示提示，开始新方案前保留原存档。无效分享链接保留当前有效方案，无有效存档时保留首页，并显示与实际状态一致的提示。分享读取结束后只移除 `plan` 参数，保留其他查询参数和页签。读取存储失败与内容损坏分别提示；保存失败时提示通过分享链接留存。

分享编码、存档键和写入形态保持原样；旧客户端仍能读取有效的新方案。本次没有远程调用，也不改变高德客户端。

## 验证与回滚

回归测试覆盖可解压但字段无效的链接、错误日期、无效枚举、负费用、嵌套自定义地点、回家设置、缺字段的旧方案和未知字段。有效方案需通过编码往返，并能继续生成计划。

运行 `npm test`、`npm run typecheck`、`npm run fonts`、`npm run build`。浏览器检查无效存档、无效分享和有效分享的启动行为、提示与查询参数；与地图服务有关的线上验证不在本次范围内。

2026-10-12 本地验证结果：上述命令全部成功，单元测试 188 项通过；新增的 4 项分享校验测试在修改前全部失败，修改后通过。浏览器检查 9 个场景通过，未捕获页面运行异常。自动化脚本保存在 `scripts/check_share_browser.py`，使用 Python Playwright 和对应版本的 Chromium，安装和运行步骤见 [README](../README.zh-CN.md#可选浏览器检查)。脚本使用隔离浏览器存储，并拦截非本地网络请求，没有验证线上高德服务或线上部署。

回滚对象为输入校验模块、`share.ts`、`App.tsx` 和对应测试、浏览器检查脚本、字体生成物。存档格式未迁移，回滚不需要转换用户数据。

## 公开协作与可复现检查

仓库是 GitHub 开源项目。补充配置前，浏览器脚本依赖本机已安装的 Python Playwright，仓库未声明安装方式；已有 `.github/workflows/data-check.yml` 只生成数据复核报告，没有检查代码测试和构建。

保留现有 Python 脚本，新增独立的浏览器测试依赖文件并在 README 说明隔离安装方式，避免引入另一套浏览器测试实现。Playwright 版本固定为本地通过 9 项检查的 `1.58.0`，来源为 `python3 -c 'from importlib.metadata import version; print(version("playwright"))'`。Python 依赖仅供可选浏览器检查，前端运行和单元测试不需要安装。

新增 GitHub Actions 工作流在 PR 和 main 分支推送时运行 `npm ci`、`npm test`、`npm run build`，Node 版本读取 `.node-version`。使用 GitHub 托管执行环境、只读仓库权限、固定官方 Action 的完整 commit SHA，并关闭 checkout 凭据持久化。这些选择依据 [GitHub Actions 安全使用建议](https://docs.github.com/en/actions/reference/security/secure-use)，可让公开 PR 接受同一套检查，无需读取部署或地图凭据。工作流仅做检查。

新增配置须通过 YAML 解析及依赖解析检查。GitHub 端运行结果需在推送后确认，本地验证不能替代 GitHub Actions 执行。回滚对象为新增 CI 工作流、浏览器依赖文件、README 安装说明和虚拟环境忽略规则。

本地已通过 CI YAML 解析，并核对触发事件、只读权限、Action SHA 和执行命令。`python3 -m pip install --dry-run --no-index -r scripts/requirements-browser.txt` 成功，声明的 Playwright 版本与已验证环境一致；未执行全新环境安装或 GitHub 端工作流。
