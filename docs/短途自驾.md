# 自定义短途自驾

[English](short-trips.md)

## 范围与选择

独立生成短途路书：选择出发点、目的地和按顺序排列的途经点，设置出发日期、总天数、单程或往返、选路策略和每日驾驶上限。全国路书、导出与 `wanlilushu.input.v2` 存档保持兼容。自由文本要求保留为备注，不自动解释成规划约束。自动推荐景点、酒店和核实当地价格不在本次实现范围内。

全国规划器依赖闭合且经过资料整理的路线数据（`src/lib/plan.ts`、`src/lib/order.ts`）。现有 `src/components/AddPlace.tsx` 只搜索地点并计算插入环线的两条替代路段。直接复用环线会带入无关的全国站点。因此采用独立规划器，复用高德加载器和坐标转换，不修改全国排程规则。

| 方案 | 收益 | 代价 |
|---|---|---|
| 修改全国规划器 | 复用已有站点详情 | 任意地点缺少环线要求的资料，现有调用方和存档需要迁移 |
| 独立短途规划器（采用） | 支持任意起终点及每日驾驶上限，兼容旧路书 | 单独维护行程视图与存档校验 |

首页和全国路书工具栏提供短途入口。只有短途规划器调用新的搜索及驾车适配模块，原有加入地点和地图分支不变。地点、路线内部使用 WGS84，高德边界转换为 GCJ-02。搜索候选仅临时显示；与现有自定义站点一致，只保存用户主动选入行程的地点，不保存商家目录。

## 远程调用与存档

使用高德 JS API 2.0 的[地点搜索和驾车规划](https://a.amap.com/jsapi/static/doc/index.html)，策略对应文档中的 `LEAST_TIME`、`LEAST_FEE`、`LEAST_DISTANCE`。里程、时长来自实际路网结果，返程按实际方向重新查询。未配置 Key、查询失败、返回异常或超时均报错，不用直线补成驾车路线。

SDK 管理连接、连接池及底层重试，公开 JS API 没有独立配置连接、读取、连接池等待超时的接口。应用设定的截止时间约束界面等待，无法保证终止 SDK 后台请求：单次搜索等待最多 15 秒，完整生成过程（加载 SDK 及顺序查询全部路段）等待最多 60 秒。这是界面响应期限，不是网络性能结论。应用不自动重试。最多五个途经点，含直接返程最多七次驾车查询，全部成功才展示路书；过期回调不能覆盖新状态。不修改共享加载器和客户端配置。

短途条件使用 `wanlilushu.short.v1`，恢复前校验字段。计算出的路线不持久保存，需要重新生成。全国存档 Key 和压缩分享格式不变。短途支持 Markdown、GPX 导出和打印，不使用全国路书分享链接。

## 排程、验证与回滚

按照地点顺序在每日驾驶上限内安排路段。富余天数留给目的地，返程在最后一天结束。总天数不足时拒绝生成，显示至少需要的驾驶天数。跨天路段标明中转住宿地点待选，拆分到每日的公里数按时长比例估算；完整路段保留高德里程、时长。驾驶上限计算不含休息、游览和临时拥堵，不虚构酒店、营业时间或宠物准入政策。

验证当天往返、天数不足、长路段拆分、途经顺序、返程方向差异、跨年日期、损坏存档、缺失 Key、超时、过期结果、导出及原有全国功能。运行 Vitest、TypeScript、生产构建和隔离浏览器检查。真实高德验证依赖可用 Key 和网络，结果与模拟浏览器测试分开报告。

回滚移除短途入口及新模块，独立存档 Key 可保留不用。全国数据和存档无需反向迁移。
